# تجهيز حيّنا للنشر على iOS وApp Store

هذا الدليل خاص بمستودع `youef/app_ksa_test`. المشروع يستخدم Expo Router وReact Native، وملفات `app.json` و`eas.json` تحتوي بالفعل على إعدادات iOS وملفات بناء EAS.

## ما يلزم قبل النشر

- [ ] التسجيل في Apple Developer Program بحساب Apple شخصي مع تفعيل المصادقة الثنائية.
- [ ] قبول الاتفاقيات وانتظار تأكيد عضوية Apple.
- [ ] تسجيل الدخول إلى حساب Expo المستخدم للمشروع.
- [ ] التأكد من إمكانية الوصول إلى مشروع EAS المعرّف في `app.json`.
- [ ] مراجعة أسماء التطبيق والهوية البصرية وبيان الخصوصية وروابط الدعم.
- [ ] اختبار تسجيل الدخول والتسجيل والمحتوى والصور والخرائط والإشعارات على جهاز iPhone فعلي.
- [ ] التأكد من عدم تضمين مفاتيح سرية أو مفاتيح خدمة Supabase في التطبيق. استخدم فقط المفتاح العام المناسب للعميل، مع تفعيل سياسات RLS في Supabase.
- [ ] تقييد مفتاح Google Maps بحسب التطبيقات وواجهات API المطلوبة، وتدويره إذا كان قد نُشر دون قيود.

## إعدادات المشروع الحالية

- الاسم الظاهر: `حيّنا`
- Expo slug: `hayna`
- iOS bundle identifier: `sa.hayna.app`
- إصدار التطبيق في الإعداد الحالي: `1.0.0`
- ملف بناء المتجر: `eas.json`، ملف `production`
- ملف بناء الاختبار: `eas.json`، ملف `testflight`

تحقق من أن معرّف الحزمة متاح في حساب Apple قبل تثبيته نهائياً؛ يجب أن يظل متطابقاً في إعدادات التطبيق وسجل App Store Connect.

## خطوات البناء السحابي (لا تحتاج إلى Mac)

يمكن تشغيل هذه الأوامر من بيئة تطوير أو طرفية تدعم Node.js. لا تضع كلمات المرور أو مفاتيح API السرية داخل المستودع.

```bash
npm install
npx expo-doctor
npx eas-cli@latest login
npx eas-cli@latest project:info
npx eas-cli@latest build --platform ios --profile production
```

في أول بناء، اتبع تعليمات EAS لتسجيل الدخول إلى Apple وإنشاء/اختيار بيانات التوقيع. لا يمكن تنفيذ التوقيع النهائي للمتجر قبل توفر حساب Apple Developer المدفوع.

## إنشاء سجل التطبيق ورفعه

1. بعد تفعيل العضوية، افتح [App Store Connect](https://appstoreconnect.apple.com/).
2. أنشئ تطبيقاً جديداً باسم `حيّنا`، واختر iOS والـ Bundle ID المطابق `sa.hayna.app` واللغة الأساسية المناسبة.
3. أكمل بيانات الخصوصية والتصنيف العمري وحقوق المحتوى وبيانات التواصل.
4. جهّز أيقونة ولقطات شاشة أصلية من التطبيق، ورابط سياسة الخصوصية ورابط الدعم.
5. بعد نجاح بناء EAS، ارفع النسخة:

```bash
npx eas-cli@latest submit --platform ios
```

6. اختبر النسخة في TestFlight أولاً، بما في ذلك إنشاء حساب وتسجيل الدخول والروابط والإشعارات وسلوك الخريطة وطلبات أذونات الموقع والصور.
7. في App Store Connect، اربط النسخة بصفحة الإصدار، أكمل البيانات المطلوبة، ثم أرسلها إلى App Review. الرفع إلى App Store Connect أو ظهورها في TestFlight لا يعني أنها نُشرت للعامة.

## قائمة فحص قبل طلب المراجعة

- [ ] لا توجد شاشات فارغة أو أخطاء وقت التشغيل أو أزرار غير فعالة.
- [ ] يعمل التطبيق عند رفض إذن الموقع أو الصور، ولا يطلب إلا الأذونات اللازمة.
- [ ] تعمل الحسابات التجريبية التي ستُقدّم للمراجعة، إن كان التطبيق يتطلب تسجيل الدخول.
- [ ] توجد طريقة واضحة لحذف الحساب من داخل التطبيق إذا كان إنشاء الحساب متاحاً، وفق متطلبات Apple ذات الصلة.
- [ ] تتطابق سياسة الخصوصية مع البيانات التي يجمعها التطبيق ومشاركة البيانات الفعلية.
- [ ] لا يعتمد التطبيق على محتوى تجريبي أو روابط مكسورة أو خدمات غير مهيأة.
- [ ] تم اختبار الإشعارات على جهاز حقيقي، وعدم اعتبار الإذن وحده دليلاً على أن خدمة الإرسال الخلفية تعمل.

## ملاحظات مهمة

- هذا المستند يوضح المسار ولا يعني أن التطبيق اجتاز البناء أو اختبار الأجهزة أو مراجعة Apple.
- إعدادات Expo الحالية تتضمن مكتبات أصلية للخرائط والإشعارات والصور والموقع؛ لذلك يجب اختبار بناء iOS فعلياً بدلاً من الاكتفاء بمعاينة الويب.
- راجع متطلبات Apple الحالية قبل الإرسال: [الانضمام إلى Apple Developer Program](https://developer.apple.com/programs/)، [إرشادات إرسال iOS من Expo](https://docs.expo.dev/submit/ios/)، و[إرشادات مراجعة App Store](https://developer.apple.com/app-store/review/guidelines/).
