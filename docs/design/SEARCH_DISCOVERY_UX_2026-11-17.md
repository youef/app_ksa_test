# خطة تصميم صفحة الاستكشاف والبحث — 2026-11-17

## النطاق والأولوية
الصفحة الوحيدة في هذه الدفعة: `app/search.tsx`. الأولوية لتحسين شريط البحث، تصنيفات النتائج، الحالات الفارغة، الوصولية والتجاوب. لا تغييرات على قاعدة البيانات أو المسارات الأخرى.

## تحليل قبل التنفيذ
- شريط البحث 44px وزر مسح 24px؛ أهداف اللمس صغيرة خصوصًا على iPhone/Android.
- تبويبات التصنيف لها `tabActive` بخلفية شفافة ونص أبيض، ما يضعف التباين.
- حاوية النتائج تمتد بكامل عرض iPad/Web دون حد عرض.
- حالة الخطأ في البحث تتحول إلى «لا توجد نتائج»؛ رسالة غير دقيقة.
- بطاقات الأشخاص تظهر نقطة «متصل» دائمًا دون بيانات حضور حقيقية.
- لا توجد تسميات وصول واضحة للتبويبات والبحث وزر المسح.
- منطقة التحميل فارغة إلا من مؤشر واحد.

## تصميم التنفيذ
1. توحيد ألوان التحكم باستخدام OASIS وإبراز التبويب النشط بخلفية أساسية ونص أبيض؛ الحد الأدنى لأهداف اللمس 44px.
2. منطقة محتوى متجاوبة بحد عرض 860px، ومركزية على الشاشات الواسعة، مع الحفاظ على RTL.
3. تسميات وصول وحالة اختيار التبويب، وتسميات إدخال البحث ومسح النص.
4. فصل حالة الخطأ عن حالة الصفر نتائج مع زر إعادة المحاولة.
5. إلغاء شارة الاتصال المضللة، وإظهار علامة التحقق فقط للحسابات الموثقة.
6. تحسين نصوص الحالة الفارغة والتحميل دون طلبات شبكة إضافية.

## خطة التحقق
- `npm run typecheck`
- `npm run build` (Expo web + metadata)
- `node --test tests/*.test.mjs` إن توفرت الاختبارات
- مراجعة diff وCI وVercel، لا دمج أو نشر دون النجاح والمراجعة.
