# حيّنا | تحسين مركز التوثيق — 19 نوفمبر 2026

## نطاق الدفعة
المكوّن `components/account/AccountCenter.tsx` عند فتح `/profile?tab=verification` أو `section=identity` فقط. لا تغييرات في قاعدة البيانات، معالجة الاعتماد الإداري، التصاريح، أو التحقق الحكومي، ولا مساس بمشروع آخر.

## المشكلة قبل التنفيذ (من لقطة iPhone)
- بطاقة تعريف بالملف الشخصي فيها أيقونة «عرض الملف» مكررة مع زر المعاينة في الهيدر.
- صندوق تعريفي «مركز توثيق حسابك» ثم بطاقة كبيرة تكرر الوصف وحالة الحساب، تاركة مساحات بلا قيمة عملية.
- حالة «الحساب غير موثق» تفتقد تفسيرًا قصيرًا لما يجب فعله، والاعتماد بعد مراجعة الإدارة غير ظاهر بما يكفي.
- فتح تغيير نوع الحساب يعرض قائمة طويلة وأسئلة في مسار واحد يصعب مسحه بصريًا.
- لم يكن خطأ تحميل طلب التوثيق منفصلًا عن حالة «لم يقدّم طلبًا»: قد يؤدي لعرض وصف مضلل وتشجيع المستخدم على إرسال طلب مكرر.

## خطة UX/UI
1. ترسيخ صفحة «توثيق الحساب» مع تبويب مختصر، وإزالة بطاقة الحساب المكررة من هذه الصفحة فقط.
2. ملخص واحد يجمع الاسم والصورة والصفة الحالية وشارة حالة الاعتماد، اعتمادًا على بيانات الملف والطلب.
3. عرض الطلب المعلّق أو المعتمد أو المرفوض، مع تاريخ التقديم وموعد المراجعة إن كان متاحًا، دون الادعاء بقبول آلي.
4. زر أساسي واحد لفتح نموذج التوثيق، مع تعطيل فتحه إذا كان الطلب معلقًا أو الحالة غير متاحة.
5. داخل النموذج: اختيارات واضحة من عمودين عندما يتسع الهاتف، حقل أو مستند حسب النوع، ورسالة جاهزية للإرسال قبل الضغط.
6. الإبقاء على النماذج المتخصصة للسجل التجاري ووثيقة العمل الحر كما هي وربطها بنظام المراجعة الحالي.
7. إضافة زر تحديث يدوي، ودعم RTL وأهداف لمس لا تقل عن 44 نقطة، وتباين لوني وحالات فراغ وخطأ حقيقية.

## التنفيذ — قبل ← بعد
- قبل: ثلاث بطاقات تتكرر فيها الهوية/التوثيق. بعد: بطاقة حالة واحدة وبطاقة إجراء واحدة وتلميح سفلي صغير.
- قبل: قائمة عمودية طويلة لأنواع الحسابات. بعد: بطاقات RTL قابلة للقراءة من عمودين على الشاشات المناسبة وعمود واحد عند العرض الضيق.
- قبل: زر الإرسال يفحص المرفقات بعد الضغط. بعد: رسالة جاهزية ومعايير تفعيل مع توضيح الإثبات واسم النشاط المطلوب.
- قبل: فشل تحميل الطلب يظهر كعدم وجود توثيق. بعد: تنبيه «تعذر التحقق من الطلب»، ومنع إرسال طلب جديد حتى تحديث البيانات.
- قبل: طلب قيد المراجعة يمكن أن يفتح نموذج غير مفيد. بعد: تعرض الحالة وتاريخ التقديم فقط حتى انتهاء المراجعة.
- قبل: اكتشاف تحديث الحالة يعتمد على السحب. بعد: زر «تحديث الحالة» واضح ومناسب لذوي الإعاقة.

## اختبارات ومعايير قبول
- CI: فحص TypeScript، اختبار حزم Web وAndroid وiOS، والاختبارات الموجودة في GitHub Actions.
- مراجعة يدوية مستقبلة: حساب غير موثق؛ قيد المراجعة؛ مرفوض؛ معتمد؛ تعذر تحميل الطلب؛ مستندات رسميّة لمستقل وتاجر؛ iPhone 375/414 وiPad والويب في الوضعين الفاتح والداكن.
- لا يعني نجاح CI اكتمال معاينة فعلية أو قبول إداري، ولا يُدمج PR قبل نجاح الفحوص.
