# Search UI design plan — 2026-11-08

## Scope
Only `app/search.tsx`. Previous batches: live (#95 merged), favorites (#96 open), notifications (#97 open). This batch: search.

## Before / UX audit
- City filter is a visually small left-aligned toggle with no selected accessibility state.
- Search field and clear button lack accessible labels; clear button's 24px target is below 44px guidance.
- Category pills have no selected state or explicit accessible role; horizontal scrolling direction is brittle for RTL.
- Loading status has no live accessibility announcement; empty state can strand users on a category without a quick reset.
- Recent-search clear action has a small hit target.

## Design execution
1. Use OASIS colors and minimum 44–48px targets; align city filter to RTL reading edge and expose pressed state.
2. Add search field label, clear action label, search tabs' selected states, and accessible loading/result announcements.
3. Offer one-tap reset of the category filter from empty results, keeping the existing search term.
4. Keep AppHeader, existing safe-area/bottom-nav inset, Supabase search, debouncing, and existing result card navigation unchanged.
5. Reduce visual noise; avoid animated layout shifts, new dependencies, or background fetches.

## Validation gates
TypeScript, Expo web bundle, existing repository tests and any required review; no merge or production deploy until all pass.

## After / acceptance
- Keyboard and screen readers identify search, filters and reset actions.
- RTL and responsive widths retain horizontal scrolling and bottom navigation clearance.
- Empty search state can reset filters without retyping.
- No search API or RLS changes.
