# خطة تحسين واجهة تسجيل الدخول وإنشاء الحساب — 2026-11-23

## الهدف والأولوية
تحسين تجربة أول دخول إلى حيّنا في `app/auth.tsx` فقط. شاشة المصادقة هي نقطة دخول الزائر والمستخدم الجديد، لذا الأولوية لتوضيح اختيار الوضع، تحسين النماذج العربية على الهاتف والويب، وإظهار الأخطاء بطريقة مفهومة وقابلة للوصول.

## خط الأساس قبل التنفيذ
- الفرع الأساسي: `main`؛ فرع العمل: `design/auth-ux-20261123-1200`.
- الشاشة تستخدم `AppHeader` المشترك الذي يطبق Safe Area العلوية، و`OasisSurface` و`OasisTextInput` و`HaynaActionButton`.
- المحتوى محدود العرض ومتمركز، لكن بطاقة النموذج ذات نصف قطر 14px وخلفية فاتحة شبه ثابتة، وكذلك غلاف الحقول وبعض الحدود؛ وهذا لا يتبع لوحة OASIS بصورة كاملة في الوضع الداكن.
- ارتفاع غلاف الحقل 44px، وزرا تبديل الدخول/التسجيل يستخدمان نمط chip المضغوط، فلا يقدمان مساحة اختيار متسقة بوضوح مع أهداف اللمس القياسية.
- رسائل التحقق وأخطاء Supabase ونجاح التسجيل غير الفوري تظهر عبر `Alert.alert`؛ في الويب لا تكون جزءًا من تدفق النموذج المرئي، كما أن قارئ الشاشة لا يجد منطقة رسالة ثابتة داخل الصفحة.
- حقول البريد وكلمة المرور ومعرّف المستخدم لا تعلن جميعها تسميات/تلميحات وصول صريحة أو بيانات الإكمال التلقائي المناسبة.
- لوحة المفاتيح تدعم `KeyboardAvoidingView` و`ScrollView`، ويجب الحفاظ عليهما وعدم تغيير سلوك التمرير أو مسارات المصادقة.

## خطة التصميم التفصيلية
1. **هوية OASIS والسطوح:** إزالة الخلفيات البيضاء شبه الثابتة من بطاقة النموذج والحقول، وربطها بألوان `useTheme()` و`OasisSurface`؛ توحيد نصف قطر البطاقة إلى 22px، الحدود إلى لون `colors.line`، وتوفير تباين متوازن في الوضعين الفاتح والداكن.
2. **اختيار الوضع:** تحويل مبدّل «تسجيل الدخول / إنشاء حساب» إلى مجموعة radio دلالية عربية؛ يعلن كل خيار حالة `selected` وتكون مساحة اللمس 48px على الأقل، مع إبقاء النص والأيقونة والاتجاه RTL.
3. **حقول النموذج:** رفع ارتفاع الغلاف إلى 48px، توحيد الحدود والتركيز على ألوان الثيم، وإضافة `accessibilityLabel` و`accessibilityHint` وخصائص الإكمال التلقائي المناسبة للبريد واسم المستخدم وكلمة المرور. الحفاظ على محاذاة RTL وأحجام النص المرنة.
4. **إظهار الأخطاء والنتائج:** استبدال تنبيهات التحقق/فشل المصادقة/نجاح التسجيل غير الفوري برسالة مضمنة داخل بطاقة النموذج، مع دور alert وإعلان حي؛ تمييز الخطأ عن رسالة النجاح بألوان OASIS. لا تغيير في رسائل العمل أو طلبات Supabase أو شروط التحقق أو وجهات التنقل.
5. **إظهار كلمة المرور:** جعل زر الإظهار/الإخفاء هدف لمس ثابتًا لا يقل عن 44×44px، مع الاسم العربي وحالة واضحة.
6. **التجاوب وSafe Area:** الحفاظ على `AppHeader` وSafe Area العلوية و`KeyboardAvoidingView` والتمرير الحالي؛ إضافة مساحة سفلية من `useSafeAreaInsets()`، والحفاظ على حد عرض 472px لتجنب تمدد النموذج على iPad/Web.
7. **الحركة والأداء:** عدم إضافة مكتبات أو صور أو حركة مستمرة؛ الإبقاء على حالات الضغط الخفيفة التي يوفرها `OasisPressable`، وتجنب أي عمل إضافي عند كل render.

## قبل / بعد ومعايير القبول
- **قبل:** بطاقة ذات 14px radius وخلفية ثابتة → **بعد:** بطاقة OASIS بزاوية 22px وألوان متكيفة مع light/dark.
- **قبل:** تبديل وضع مضغوط بلا selected semantics → **بعد:** radio group عربية بخيارات 48px وحالة اختيار معلنة.
- **قبل:** حقول 44px بلا تسميات وصول صريحة → **بعد:** حقول 48px مع labels/hints وautocomplete.
- **قبل:** Alert منفصل للتحقق والأخطاء ورسالة التسجيل → **بعد:** منطقة حالة مضمّنة قابلة للقراءة داخل النموذج.
- **قبل:** زر عين صغير متغير المساحة → **بعد:** هدف 44px ثابت.
- يجب الحفاظ على جميع استدعاءات `supabase.auth.signUp` و`signInWithPassword` و`is_username_available`، والتحقق من المدخلات، ورسائل الترجمة الحالية، والانتقال إلى `/home`، وخيار التصفح كزائر.
- لا تعديل على قاعدة البيانات أو API أو المصادقة أو صلاحيات الحساب أو أي صفحة أخرى.
