- الفرع الأساسي: `main`، الالتزام الذي بُنيت عليه هذه الدفعة: `562e97be6eb21c9e3067fa928443cf571de4391a`.

- الاستخدام من `app/business.tsx` لا يتطلب تعديل الشاشة الأم أو تدفق بياناتها.

### خطة التنفيذ — تحسين UX واحد
1. إضافة حالة مستقلة لفشل تحميل الشعار، دون إعادة استخدام حالة فشل الغلاف.
2. إعادة ضبط حالة الشعار عند تغير المنشأة أو مصدر رابط الشعار حتى لا تنتقل حالة الفشل من منشأة إلى أخرى أو من صورة قديمة إلى صورة جديدة.
3. إضافة `onError` إلى صورة الشعار، وعند الفشل عرض أيقونة الفئة الموجودة أصلًا داخل صندوق الشعار.
4. الحفاظ على أبعاد الشعار، `contain`، ترتيب RTL، علامة التوثيق، استعلامات البيانات، وأزرار التواصل والتنقل.
5. إضافة اختبارات مصدرية مركزة تؤكد استقلال حالة الشعار، معالج الخطأ، والـfallback.
6. تشغيل TypeScript وتصدير Web والاختبارات المركزة والمتاحة؛ ثم مراجعة نتائج GitHub Actions قبل فتح Draft PR.

### النطاق والقيود
- الملفات المقصودة: `components/market/BusinessDetailsSheet.tsx`، `tests/businessDetailsPartialRetry.test.cjs`، وهذه الوثيقة.
- لا تعديل لـ`app/market.tsx` أو `app/business.tsx`، ولا API/DB/RLS أو تخزين صور أو سياسات أو صلاحيات.
- لا إضافة حركة؛ لذا لا تغيير لسلوك تقليل الحركة.
- لا دمج ولا نشر إنتاجي. يظل الطلب Draft حتى اكتمال الفحوص والمراجعة البشرية.

### معيار القبول
- صورة الشعار الصحيحة تستمر بالظهور كما هي.
- URI فاشل يعرض رمز الفئة بدل مساحة فارغة.
- تغيير المنشأة أو رابط الشعار يعيد محاولة العرض ولا يرث فشل الصورة السابقة.
- جميع اختبارات الاسترداد الحالية تظل ناجحة.
- فحوص TypeScript وWeb وCI ناجحة، أو توثيق أي فحص غير متاح/متوقف بوضوح.

### الدفعة التالية
العودة بالتناوب إلى الملف الشخصي، مع إعادة فحص PRs المفتوحة واختيار عيب UX واحد غير متعارض قبل لمس أي ملف.

## بعد التنفيذ — 2026-11-26

- أُضيفت حالة `logoFailed` مستقلة عن `imageFailed` الخاصة بالغلاف.
- أصبحت صورة الشعار تتعامل مع `onError`، وتعرض رمز الفئة نفسه عند فشل التحميل بدل إبقاء صندوق فارغ.
- تُصفّر حالة فشل الشعار عند تغيّر معرّف المنشأة أو URI الشعار؛ فلا تنتقل حالة فشل قديمة إلى بطاقة منشأة أخرى أو صورة جديدة.
- بقيت صورة الغلاف وسلوكها، واستعلامات القراءة، وحالة ساعات العمل والعروض، وروابط الخدمة والمنتج والتواصل كما هي.
- أضيف اختباران إلى `tests/businessDetailsPartialRetry.test.cjs` لحالة fallback وإعادة الضبط.
- لم تُضف أي حركة أو اعتماد جديد، ولم تُعدّل أي شاشة أخرى.

### التحقق
- لم يمكن تشغيل الاختبارات محليًا: تعذّر استنساخ المستودع في بيئة التنفيذ بسبب فشل DNS للوصول إلى `github.com`.
- لم يُدّع نجاح TypeScript أو Expo Web محليًا؛ سيتم الاعتماد على فحوص GitHub Actions المرتبطة بطلب الدمج، وتحديث هذه الوثيقة وملخص PR بنتائجها الفعلية.
- QA مرئي على أجهزة iPhone/Android وVoiceOver/TalkBack ما زال مطلوبًا.

### نتيجة ما قبل/بعد
- **قبل:** URI شعار غير صالح يبقي مساحة الشعار بلا صورة أو رمز، رغم وجود fallback مماثل للغلاف.
- **بعد:** فشل الشعار يُظهر أيقونة نوع المنشأة فورًا، مع إعادة محاولة تلقائية عند تغيّر مصدر الصورة.

### الدفعة التالية
الملف الشخصي — إعادة مراجعة PRs المفتوحة واختيار إصلاح واحد غير متعارض.
