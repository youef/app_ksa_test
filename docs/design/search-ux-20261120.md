# Search UX polish — 2026-11-20

## Plan (before implementation)
- **Scope:** `app/search.tsx` only, plus this design record. No search/query/backend behavior changes.
- **Audit baseline:** Search input is 48px high, clear button is 44px, but category pills (38px), city-scope toggle (34px), suggestion chips (36px), recent-search delete (27×36px), discovery-focus button (38px), and recent/history affordances are below or close to a comfortable 44px touch target. Enter submits into the debounce path without explicitly dismissing the keyboard. Loading text and result count are visually present but lack explicit live announcement semantics.
- **Visual direction:** Keep the existing Oasis palette, RTL composition, search field, tabs, and card hierarchy; make small controls feel calmer and consistently sized. Increase result cards to 16px corners and 14px internal padding while preserving the lightweight border and low-shadow treatment.
- **Interaction/accessibility:** Make common search/filter/history actions at least 44px tall/wide; explicitly dismiss the keyboard on submit; announce loading and dynamic result count to assistive technology. Preserve reduced-motion behavior, current filter/query semantics, and all navigation.
- **Responsive:** Maintain horizontal RTL tabs (scrollable on narrow iPhone/Android), centered web content max-width, and bottom-nav inset. No fixed-width layout or new animation is introduced.
- **Risk/validation:** UI-only style and accessibility props. Check the patch remains confined to the search page; run TypeScript, Web export, and available Node tests when runtime allows. Manual iPhone/Android/iPad/keyboard/screen-reader review is still required before merge.

## Before / after
- 34–38px city filter/category buttons and 27×36px recent-search removal target → minimum 44px targets.
- 36px suggestion chips and 38px discovery focus → 44px touch targets.
- 12px cards / 8px gaps → 16px cards / 10px gaps for a softer, less cramped visual rhythm.
- Enter may leave keyboard visible → submit explicitly blurs the search field.
- Loading and result count only visual → progress/result count exposed as polite accessibility updates.
