# دفعة إدارة السوق والمنشآت — 31 أكتوبر 2026

- جُمعت نسخة main الحديثة مع تجهيز PayPal السابق في فرع مستقل، مع الحفاظ على خلفيات التطبيق والتنقل.
- أضيف مدخل «إدارة السوق والدفع» إلى الإدارة والمزيد، ولوحة جاهزية PayPal إلى صفحة السوق ووكيل الإدارة. تعرض وجود الإعدادات دون قيم الأسرار، وحالة مخطط الدفع، واختبار مصادقة PayPal بطلب صريح دون إنشاء دفعة.
- نُشرت marketplace-admin بالإصدار 4 مع JWT مفعّل. التحقق من الجلسة وصلاحية مراجعة السوق يسبق قراءة الإعدادات. طابق المصدر الحي السابق مصدر المستودع قبل استبداله. لم تُعدل أسرار الخادم أو إعداد التحصيل الفعلي.
- استُبدلت تأكيدات اعتماد ورفض الحملات بنافذة مشتركة للويب والجوال؛ لا تزال قاعدة البيانات تتحقق من الدفع والصلاحية. رفض الحملة لا يعني تنفيذ استرداد مالي. أخطاء جلب القائمة لا تُعرض كقائمة فارغة ناجحة.
- الدليل يدعم «مدينتي كاملة / حيّي»، ويطبق الفلترة قبل تحميل الدفعات. بقي نطاق المدينة هو الافتراضي.
- أسعار خدمات المنشأة تستخدم منسق صفحة الخدمة نفسه، مع جلب الحد الأعلى للسعر بدل إخفائه.
- وكيل الإدارة يمنع المستخدم المحظور من واجهته، ويمسح بيانات الجلسة السابقة أثناء التحقق. وصفه يوضح حدود الإصلاح الآلي الفعلية بدل ادعاء إصلاح كل الأعطال.

## التحقق والحدود

نجحت مجموعة الاختبارات المحلية الموسعة: 219 اختبارًا دون فشل، ونجح TypeScript. تشمل الاختبارات رفض قراءة إعدادات الدفع لغير المسجل وغير المصرح، وعدم إعادة قيم الأسرار، واختبارات PayPal المعزولة. لم يُختبر فتح لوحة الدفع بحساب مدير فعلي أو على أجهزة؛ اختبار HTTP الحي دون اعتماد لم يحصل على استجابة بسبب تعذر الشبكة من الطرفية.

أكد صاحب الحساب أنه لم يُرقَّ إلى Business. لذلك **لم يُفعّل PayPal الحقيقي**، ولم يُطبق مرشح SQL أو تُنشر دوال تحصيل PayPal الجديدة، ولم تُنشأ معاملات. تعديل قيم الأسرار ما زال عبر أسرار Supabase؛ هذه الدفعة تضيف الحالة واختبار الاتصال، ولا توفر كتابة المفاتيح أو مفتاح تشغيل مالي يتجاوز المتطلبات. يلزم استكمال حساب Business وSandbox والتسويات والاسترداد الجزئي والعكس قبل اعتماد Live. راجع paypal-activation.md.

لم تُطبق أي ترحيلات قاعدة بيانات ضمن هذه الدفعة، ولا يُعد هذا التقرير إثبات اكتمال الأنظمة الأربعة عشر أو جميع إعدادات الدفع.
